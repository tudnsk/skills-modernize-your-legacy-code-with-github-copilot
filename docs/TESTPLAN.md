# COBOL Accounting System Test Plan

This test plan describes the current behavior of the school accounting system and is intended for review with business stakeholders before creating equivalent unit and integration tests in the Node.js application.

| TC-011 | Debit the account with zero | The application is running. | 1. Select `3`.<br>2. Enter `0.00`.<br>3. Select `1`. | Business expectation: the system rejects zero as an invalid debit, or clearly confirms that no balance change occurred. | To be recorded during stakeholder validation. | Not Run | Current COBOL code does not explicitly validate that a debit is positive; confirm the desired Node.js behavior. |
| TC-012 | Debit the account with a negative amount | The application is running. | 1. Select `3`.<br>2. Enter a negative amount, such as `-10.00`. | Business expectation: the system rejects the amount and leaves the balance unchanged. | To be recorded during stakeholder validation. | Not Run | Without validation, subtracting a negative amount could increase the balance; this is a transformation risk to resolve. |
| TC-013 | Reject an invalid menu selection | The application is running. | 1. Enter `0`, `5`, or another value outside `1`-`4`.<br>2. | TC-014 | Exit the application | The application is running. | 1. Select `4` (Exit). | The application stops prompting, displays `Exiting the program. Goodbye!`, and terminates normally. | To be recorded during stakeholder validation. | Not Run | Covers the loop termination condition. |
| TC-015 | Preserve multiple transactions during one session | The application is running with a balance of `1000.00`. | 1. Credit `100.00`.<br>2. Debit `25.00`.<br>3. Credit `10.50`.<br>4. | TC-017 | Handle a monetary value at the supported upper boundary | The application is running. | 1. Attempt a transaction that results in a balance no greater than `999999.99`.<br>2. | TC-018 | Handle a transaction that exceeds the supported numeric range | The application is running with a balance near the upper boundary. | 1. Attempt a credit that would produce a balance greater than `999999.99`.<br>2. View the balance and observe any runtime response. | Business expectation: reject the transaction with a clear error and preserve the previous balance. | To be recorded during stakeholder validation. | Not Run | Current COBOL behavior for numeric overflow should be characterized before reproducing it in Node.js. |

## Validation Notes

- Record the observed output in **Actual Result** and set **Status (Pass/Fail)** after each execution.
- Stakeholders should resolve the expected behavior for zero and negative amounts, overflow, and persistence before the Node.js test suite is finalized.
- Unit tests should isolate balance calculations and validation rules. Integration tests should verify menu or API routing through operations and data storage, including the multi-transaction flow in TC-015.
